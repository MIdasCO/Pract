# Git Flow

Основная схема работы в этом репозитории:

- `main` - только стабильные релизы.
- `develop` - интеграционная ветка для готовящихся изменений.
- `feature/*` - отдельные задачи и фичи.
- `hotfix/*` - срочные исправления для `main`.
- `release/*` - подготовка релиза перед слиянием в `main`.

Рекомендуемый поток:

1. Создавать новую задачу из `develop`:
   - `git checkout develop`
   - `git checkout -b feature/<name>`
2. После завершения фичи сливать обратно в `develop`.
3. Для релиза создавать `release/<version>` из `develop`.
4. Срочные исправления делать в `hotfix/<name>` от `main`, затем влить и в `main`, и в `develop`.

Короткий набор правил:

- Один коммит - одна логическая правка.
- Названия веток держать короткими и понятными.
- Перед merge проверять, что backend поднимается через Docker Compose.
